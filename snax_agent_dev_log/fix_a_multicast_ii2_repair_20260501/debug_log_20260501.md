## Initial Debug Notes

- Current source inspection shows the original single-slot logic in `DualVersaCoreSwigluGen.scala`: `stream2acc_0_ready_o = !a_buf_valid`, per-VC `a_buf_sent_*` bits, and A data wired directly from `a_buf_data`.
- This confirms the source still structurally prevents same-cycle pop+push on A.

## Attempt 1: 2-entry A FIFO

- Source edit replaces the old `a_buf_valid/a_buf_sent_*` replay slot with `a_fifo_data_0`, `a_fifo_data_1`, and `a_fifo_count`.
- `stream2acc_0_ready_o = (a_fifo_count != 2) || a_joint_fire`, so a full FIFO can accept a new A beat when the current head is issued in the same cycle.
- `vc0_in_a_valid` and `vc1_in_a_valid` are both driven by `a_joint_fire`; there is no per-VC single-consumer sent state.
- VC capability is derived from `!keep_output_reg && !keep_output_next && B_valid` for each VC, avoiding direct dependence on `vc*_in_a_ready`.
- `rtl-gen` succeeded for Attempt 1. The generated shell wrapper has `stream2acc_0_ready_o = (a_fifo_count != 2'd2) || a_joint_fire` and both VC A inputs wired to `a_src_data`.
- Direct S6 simulation of Attempt 1 did not complete S0 Mode0. The likely drop window is immediately after launch: the wrapper can see A and B valid before the VC exposes `busy_o=1`. Internally, `DecoupledCatNto1` also requires the subtraction input valid (`cstate === sBUSY`), so the VC does not consume even though the wrapper's external capability gate allowed `a_joint_fire`.

## Attempt 6: Narrow to one fall-through A slot

- Temporary wrapper instrumentation showed Attempt 5 no longer stalls at A/B input startup: both A and B handshakes fire.
- The later stall moved to the output side: both output assemblers had valid data while both stream writer ready signals were low.
- Counter instrumentation showed output handshakes running ahead of matched VC D accepts under the two-entry A FIFO experiment, so the two-entry prefetch is too aggressive for the existing shell/post-process/output path.
- Replaced the two-entry A FIFO with a single fall-through A slot:
  - if the slot is empty, A can pass directly to both VCs;
  - if the slot is full, the streamer can push a replacement in the same cycle the current slot is accepted by both VCs;
  - the slot only advances on actual dual VC A ready, preserving atomic shared-A consume.
- This keeps the intended II=1 repair (`ready` no longer drops for a whole cycle after every accepted beat) while avoiding an extra beat of A prefetch beyond the old shell contract.
- `rtl-gen`, `sw`, and `bin/snitch_cluster.vlt` all completed successfully.

## Attempt 8: Post-compute A reader drain

- Added a run-seen latch on accepted CSR start and a sticky post-compute drain state after both VCs return to idle/control-ready.
- During normal compute, A still advances only on actual dual VC A ready (`vc0_in_a_ready && vc1_in_a_ready`), preserving atomic shared-A consume.
- During post-compute drain, leftover A reader beats are accepted without presenting them to either VC. This is only enabled after a real accelerator launch has completed, avoiding the startup window where the streamer is started before the accelerator CSR start.
- Rationale: direct B pass-through can let the B readers complete while the A reader is behind. Once both VCs are idle, leftover A reader beats are not logical compute beats; draining them is needed so the existing streamer CSR program can finish cleanly.
- Falsified by direct S6 run: the app reached result checking, but S0 Mode0 output mismatched immediately (`output[0] = -21`, golden `-14`, plus many more). Therefore the leftover A beats are real compute beats, and post-compute A drain/output quota is not a valid repair.

## Attempt 14: Grouped A/B issue buffer

- Replaced the A-only replay slot with a shell-local grouped issue buffer:
  - independent assembly slots collect one A beat, one B0 beat, and one B1 beat from the streamer;
  - an issue slot holds the complete logical K-step group (`A`, `B0`, `B1`);
  - VC0 sees the shared A plus B0 until its pair is accepted; VC1 sees the same shared A plus B1 until its pair is accepted;
  - the issue group retires only after both VCs have accepted their pair exactly once.
- The assembly slots can be refilled in the same cycle a complete group is moved into the issue slot, so the wrapper still targets II=1 without a global B-side serialization policy.
- This intentionally moves beyond pure B pass-through because previous direct/gated B attempts allowed the faster A-side timing to expose an output overrun. The repair remains shell-local and does not alter VersaCore internals.
- Direct S6 result: the failure moved but did not disappear. At `cyc=131072`, output emission was only `o0=1233/o1=1232` instead of the previous immediate `2817`, showing grouped issue affected the runaway path. By `cyc=196608`, the run still stalled with `o0=o1=2817`, `ow=0/0`, and both VCs busy.
