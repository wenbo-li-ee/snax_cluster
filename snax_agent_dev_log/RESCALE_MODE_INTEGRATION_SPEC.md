# Technical Specification: Dual VersaCore SwiGLU — Mode 0/1 + RescaleDown Integration

**Branch:** `swiglue`  
**Base commit:** `6c7cf48a` (minimal CSR reconfiguration for block pipeline)  
**Status:** Specification — not yet implemented

---

## 1. Motivation

The current implementation computes `(A @ W >> 2) + (A @ V >> 2)` using:
- Two VersaCores (VC0: A×W, VC1: A×V)
- `shifter_6stage.sv` (arithmetic right shift by 2, 6-stage pipeline, placeholder for SiLU)
- `shifter_2stage.sv` (arithmetic right shift by 2, 2-stage pipeline)
- `elem_adder_32b.sv` (int32 element-wise addition)
- One Writer (64ch × 64-bit = 4096b output)

The full SwiGLU computation is `(Swish(xW) ⊙ xV) @ W₂`. This spec extends the hardware to:

1. Add a **Mode CSR** to switch between SwiGLU mode and plain GEMM mode
2. Insert **RescaleDown** modules (int32 → int16) after each VersaCore path
3. Replace `elem_adder` with a real **16-bit element-wise multiplier**
4. Add a second **Writer** for dual-output in GEMM mode
5. Remove `shifter_2stage` (no longer needed)
6. Keep `shifter_6stage` as SiLU placeholder (reused with `DATA_WIDTH=16`)

---

## 2. Data Path Design

### Mode 0 — SwiGLU: `Swish(A@W) ⊙ (A@V)`

```
Reader0(A,int8) ─► VC0(int32,4096b) ─► buf0 ─► chunk_ser0
                                                    │
                                          RescaleDown0 (int32→int16, reg output)
                                                    │
                                      shifter_6stage (DATA_WIDTH=16, SiLU placeholder, >>2 on int16)
                                                    │
                                               ─────┤
                                                    │ ElemMul16b (int16×int16→int32, reg output)
                                               ─────┤
                                                    │
                                          RescaleMul (int32→int16, reg output)
                                                    │
                                         out_assemble0 (2048b) ──► acc2stream_0 ──► Writer0

Reader2(B1,int8) ─► VC1(int32,4096b) ─► buf1 ─► chunk_ser1
                                                    │
                                          RescaleDown1 (int32→int16, reg output)
                                                    │ (feeds ElemMul16b second input)
```

- Writer1 is idle in mode 0 (acc2stream_1 valid never asserted)
- `shifter_2stage.sv` is **removed entirely**

### Mode 1 — Plain GEMM: `A @ W₂` (W₂ split into two halves by column)

```
Reader0(A,int8) ─► VC0(int32,4096b) ─► buf0 ─► chunk_ser0
                                                    │
                                          RescaleDown0 (int32→int16, reg output)
                                                    │
                                         out_assemble0 (2048b) ──► acc2stream_0 ──► Writer0

Reader2(B1,int8) ─► VC1(int32,4096b) ─► buf1 ─► chunk_ser1
                                                    │
                                          RescaleDown1 (int32→int16, reg output)
                                                    │
                                         out_assemble1 (2048b) ──► acc2stream_1 ──► Writer1
```

- ElemMul16b and RescaleMul exist but are bypassed (their valid inputs held low)
- Both writers active; each writes one column half of the final output

## 4. RW CSR Layout (accelerator-side, after streamer CSRs)

The accelerator CSR base address (`DUAL_VC_CSR_ADDR_BASE`) is auto-generated by `snaxgen.py` as `STREAMER_WRITER_BUSY_CSR_LAST + 1`. With two writer-busy RO CSRs the base shifts accordingly.

```
Index   Name                       Notes
[0]     OVERWRITE_ACCUM            take_in_new_c (unchanged)
[1]     ACCUM_BOUND                a_b_input_times (unchanged)
[2]     OUTPUT_BOUND               output_times (unchanged)
[3]     SUBTRACTIONS               (unchanged)
[4]     ARRAY_SHAPE_CFG            (unchanged)
[5]     DATA_TYPE_CFG              (unchanged)
[6]     MODE                       0 = SwiGLU, 1 = GEMM  ← NEW
[7]     RESCALE0_INPUT_ZP          int32, path 0 ← NEW
[8]     RESCALE0_MULTIPLIER        uint32          ← NEW
[9]     RESCALE0_OUTPUT_ZP         int32           ← NEW
[10]    RESCALE0_SHIFT             uint8 in uint32 ← NEW
[11]    RESCALE1_INPUT_ZP          int32, path 1   ← NEW
[12]    RESCALE1_MULTIPLIER        uint32           ← NEW
[13]    RESCALE1_OUTPUT_ZP         int32            ← NEW
[14]    RESCALE1_SHIFT             uint8 in uint32  ← NEW
[15]    RESCALE_MUL_INPUT_ZP       int32, after ElemMul (mode 0 only) ← NEW
[16]    RESCALE_MUL_MULTIPLIER     uint32           ← NEW
[17]    RESCALE_MUL_OUTPUT_ZP      int32            ← NEW
[18]    RESCALE_MUL_SHIFT          uint8 in uint32  ← NEW
[19]    START                      was [6], moved   ← SHIFTED
```

**Identity (no-op) rescale parameters for debug:** `input_zp=0, multiplier=1, output_zp=0, shift=0`
→ The `RescaleDownPE` formula with these values: `(0+1)*val >> 0 + 0 = val`, then clamp to int16.
So with identity params, any int32 value that fits in int16 passes through unchanged.

## 5. New / Modified SV Resource Files

### 5.1 `rescale_down_32to16.sv` — NEW

Location: `hw/chisel_acc/src/main/resources/snax_acc/versacore/rescale_down_32to16.sv`

**Interface:**
```sv
module rescale_down_32to16 #(
    parameter int unsigned NUM_LANES = 64
)(
    input  logic                           clk_i,
    input  logic                           rst_ni,
    // Shared CSR parameters (broadcast to all lanes)
    input  logic signed [31:0]             input_zp,
    input  logic        [31:0]             multiplier,
    input  logic signed [31:0]             output_zp,
    input  logic        [7:0]              shift,
    // Data port
    input  logic [NUM_LANES-1:0][31:0]     data_i,
    input  logic                           valid_i,
    output logic                           ready_o,
    output logic [NUM_LANES-1:0][15:0]     data_o,
    output logic                           valid_o,
    input  logic                           ready_i
);
```

**Per-lane combinational logic** (implement exactly as `RescaleDownPE` in `RescaleDown.scala`):
```
zero_compensated = data_i - input_zp                    // int32
multiplied       = zero_compensated * {1'b0, multiplier} // int64
shifted_one      = 1 << (shift - 1)                     // rounding addend
shifted_data     = multiplied + shifted_one
scaled_32        = (zero_compensated >= 0) ? shifted_data + (1<<30)
                                           : shifted_data - (1<<30)
correct_shift    = (shift > 31) ? scaled_32 : shifted_data
shifted_value    = correct_shift >>> shift               // arithmetic right shift
with_output_zp   = shifted_value[31:0] + output_zp
clamped          = clamp(with_output_zp, -32768, 32767)
data_o[lane]     = clamped[15:0]                        // int16 result
```

**Registered output** — backpressure handshake:
```sv
assign ready_o = !valid_o || ready_i;
// always_ff: when (ready_o): valid_o <= valid_i; if (valid_i) data_o <= computed;
```

### 5.2 `elem_mul_16b.sv` — NEW

Location: `hw/chisel_acc/src/main/resources/snax_acc/versacore/elem_mul_16b.sv`

Mirrors `elem_adder_32b.sv` structure exactly, with:
- Input: two ports of `[NUM_LANES-1:0][15:0]` (int16 signed)
- Output: `[NUM_LANES-1:0][31:0]` (int32 signed)
- Operation per lane: `$signed(data_i_0[l]) * $signed(data_i_1[l])`
- Joint handshake: fire only when both inputs valid and output can accept
- Registered output (1-cycle latency), same `out_can_accept` pattern as `elem_adder_32b`

### 5.3 `shifter_6stage.sv` — REUSE, no modification

Keep the existing file. In `DualVersaCoreSwigluGen.scala`, change the instantiation parameter from `.DATA_WIDTH(32)` to `.DATA_WIDTH(16)`. The module already has a `DATA_WIDTH` parameter.

### 5.4 `shifter_2stage.sv` — REMOVED

Do not copy or instantiate. Delete from the resource copy list in `DualVersaCoreSwigluGen.scala`.

   Mode mux is purely combinational on `mode_sel` (static during one computation).

6. **out_assemble width:** change from `DataWidthD` to `DataWidthOut` (2048b). Output beat is `PostprocLanes × 16` bits per chunk.

7. **Resource copy list:** add `rescale_down_32to16.sv`, `elem_mul_16b.sv`; keep `shifter_6stage.sv`, `elem_adder_32b.sv` (keep adder for now, it may be useful for reference); **remove `shifter_2stage.sv`** from copy list.

## 11. `datagen.py` Changes

### Golden model update

New pipeline for mode 0:
```python
# Step 1: VC0 computes A @ W (int8 × int8 → int32)
vc0_out = block_gemm(A, W)  # shape [M_tiles*meshRow, N_tiles*meshCol], int32

# Step 2: RescaleDown0 (int32 → int16)
vc0_rescaled = rescale_down_32to16(vc0_out, input_zp=RESCALE0_IZP,
                                   mult=RESCALE0_MULT, output_zp=RESCALE0_OZP,
                                   shift=RESCALE0_SHIFT)  # int16

# Step 3: SiLU placeholder (shifter_6stage at DATA_WIDTH=16: arithmetic >>2 on int16)
vc0_silu = arithmetic_right_shift_int16(vc0_rescaled, 2)  # int16

# Step 4: VC1 computes A @ V (int8 × int8 → int32)
vc1_out = block_gemm(A, V)  # int32

# Step 5: RescaleDown1 (int32 → int16)
vc1_rescaled = rescale_down_32to16(vc1_out, input_zp=RESCALE1_IZP, ...)  # int16

# Step 6: ElemwiseMul (int16 × int16 → int32)
mul_out = vc0_silu.astype(np.int32) * vc1_rescaled.astype(np.int32)  # int32

# Step 7: RescaleMul (int32 → int16)
mode0_out = rescale_down_32to16(mul_out, input_zp=RESCALE_MUL_IZP, ...)  # int16
```

Mode 1 golden:
```python
# Input: mode0_out cast to int8 (SW quantization step done in test.c)
mode1_a = np.clip(mode0_out, -128, 127).astype(np.int8)

# VC0: mode1_a @ W2_left, then RescaleDown0 → int16
# VC1: mode1_a @ W2_right, then RescaleDown1 → int16
d0_golden = rescale_down_32to16(block_gemm(mode1_a, W2_left), ...)   # int16
d1_golden = rescale_down_32to16(block_gemm(mode1_a, W2_right), ...)  # int16
```

### W₂ matrix generation

- W₂ is int8, shape `[N0*meshCol, N1*meshCol]` where N0=mode0 output columns, N1=mode1 N parameter
- `W2_left  = W₂[:, :N1//2*meshCol]` (fed to Reader B0 in mode 1 = VC0)
- `W2_right = W₂[:, N1//2*meshCol:]` (fed to Reader B1 in mode 1 = VC1)
- For N1=2: each half has 1×meshCol = 8 columns

### Stride update for int16 output

int16 output: 2 bytes/element instead of 4.
- `Dtlstride2 = meshRow × meshCol × 2 = 16 × 8 × 2 = 256 bytes` (was 512 for int32)
- Update all Dtlstride calculations accordingly
- The granularity assertion: `Dtlstride2 % (granularity_c_d * 8) == 0` → `256 % 128 == 0` ✓
