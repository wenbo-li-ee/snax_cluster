# VersaCore Int16x4 Streamer 粒度参数探索

## 1. 粒度参数定义

VersaCore 加速器的 Streamer 使用三个粒度参数控制 TCDM 缓冲区的地址对齐：

| 参数 | 当前值 | 对齐字节数 | 对齐 Bank 数 | 控制对象 |
|------|--------|-----------|-------------|---------|
| `granularity_a` | 4 | 32 B | 4 banks | A 矩阵读取器基地址对齐 |
| `granularity_b` | 2 | 16 B | 2 banks | B0/B1 矩阵读取器基地址对齐 |
| `granularity_c_d` | 8 | 64 B | 8 banks | D0/D1 输出写入器基地址对齐 |

**计算公式**：对齐字节数 = `granularity × bankWidth / 8` = `granularity × 8`

参数定义位置：`cfg/snax_dual_versacore_int16x4_cluster.hjson` 第242-244行。

## 2. 硬件背景

### 2.1 TCDM 配置

- 64 个 Bank，每 Bank 宽度 64 bit = 8 字节
- 总容量 8192 KB = 8 MB
- 稀疏互连(sparse interconnect)：`[[16,4], [8,4], [8,4], [8,4], [8,4]]`

### 2.2 Streamer 端口分配

| Streamer | 通道数 | 空间步幅 | 每拍访问 Bank 数 | 功能 |
|----------|--------|---------|----------------|------|
| Reader 0 (A) | 16 | 8 B | 16 banks | A 矩阵输入 |
| Reader 1 (B0) | 8 | 8 B | 8 banks | B0/W 权重矩阵 |
| Reader 2 (B1) | 8 | 8 B | 8 banks | B1/V 权重矩阵 |
| Writer 0 (D0) | 8 | 8 B | 8 banks | D0 输出 |
| Writer 1 (D1) | 8 | 8 B | 8 banks | D1 输出 |

总计：48 个 TCDM 端口同时访问 64 个 Bank。

### 2.3 数据流与循环顺序

Output-stationary 数据流，循环顺序 K -> N -> M：
- **K 循环**：累加点积（A 和 B 同时读取）
- **N 循环**：遍历 N 方向的输出 tile（D 写出，B 推进）
- **M 循环**：遍历 M 方向的输出 tile

## 3. 粒度对 Bank 访问模式的影响

### 3.1 A 读取器 (16 通道)

时间步幅 `Atlstride0 = meshRow × tileSize × elem_bits / 8 = 8 × 8 × 16 / 8 = 128 字节 = 16 banks`

K 循环第 k 步时，通道 i 访问：
```
bank = (base_A/8 + k×16 + i) % 64,  i ∈ [0..15]
```

16 通道窗口每 K 步移动 16 banks：{0..15} -> {16..31} -> {32..47} -> {48..63} -> {0..15}

**周期 = 4 个 K-tile**。`granularity_a = 4` (32字节 = 4 bank 对齐) 保证基地址始终在 4-bank 边界上，使周期循环均匀覆盖所有 64 个 Bank。

### 3.2 B0/B1 读取器 (各 8 通道)

时间步幅 `B0tlstride0 = b_tile_padded = 64 字节 = 8 banks`

K 循环第 k 步时，通道 j 访问：
```
bank = (base_B0/8 + k×8 + j) % 64,  j ∈ [0..7]
```

**周期 = 8 个 K-tile**。`granularity_b = 2` (16字节 = 2 bank 对齐) 保证相邻 B tile 以 8-bank 增量在 64 bank 空间中均匀推进。

### 3.3 D0/D1 写入器 (各 8 通道)

时间步幅 `Dtlstride1 = out_elem_bits × meshRow × meshCol / 8 = 16 × 8 × 4 / 8 = 64 字节 = 8 banks`

**关键约束**：`Dtlstride1 % (bankWidth/8 × granularity_c_d) == 0`，即 `64 % (8 × granularity_c_d) == 0`

这限制了 `granularity_c_d` 的有效值为 {1, 2, 4, 8}，当前值 8 为最大有效值。

## 4. 四种粒度配置对比分析

### 配置 1：(a=1, b=1, c_d=1) — 最小对齐

| 属性 | 值 |
|------|-----|
| A 对齐 | 8 B (1 bank) |
| B 对齐 | 8 B (1 bank) |
| D 对齐 | 8 B (1 bank) |
| D 断言 | 64 % 8 = 0 PASS |

**优势**：
- 最紧凑的内存布局，零填充开销
- 适用于 TCDM 空间极度紧张的场景

**风险**：
- 缓冲区边界可能不在多 bank 边界上
- 时间步幅的 bank 循环模式不规则
- A 读取器的 16 通道可能跨越非对齐边界，增加 bank 冲突概率

**适用场景**：最大化可容纳的工作负载尺寸

### 配置 2：(a=8, b=4, c_d=8) — 对称读取器对齐

| 属性 | 值 |
|------|-----|
| A 对齐 | 64 B (8 banks) |
| B 对齐 | 32 B (4 banks) |
| D 对齐 | 64 B (8 banks) |
| D 断言 | 64 % 64 = 0 PASS |

**优势**：
- B 读取器以 4-bank 对齐开始，经过 2 个 K 步 (2×8=16 banks=256B) 后 bank 模式完全对齐
- A 读取器以 8-bank 对齐，在 2 个 K 步后即回到起始 bank 组
- bank 冲突风险进一步降低

**代价**：
- 对于当前工作负载，所有缓冲区尺寸已是 32B 的整数倍，无额外填充
- 对非对齐尺寸的工作负载，每个 B 缓冲区最多增加 24 字节填充

### 配置 3：(a=16, b=8, c_d=8) — 最大规则性

| 属性 | 值 |
|------|-----|
| A 对齐 | 128 B (16 banks) |
| B 对齐 | 64 B (8 banks) |
| D 对齐 | 64 B (8 banks) |
| D 断言 | 64 % 64 = 0 PASS |

**关键特性**：
- `granularity_a = 16` -> A 缓冲区基地址对齐到恰好 1 个 A-tile 宽度 (128B)
- A 读取器的 bank 循环从 bank 0 开始，4 个 K-tile 后精确回到相同 bank
- `granularity_b = 8` -> B 缓冲区基地址对齐到恰好 1 个 B-tile 宽度 (64B)
- B 读取器的 bank 模式以 8 个 K-tile 为完美周期

**优势**：
- 最大化 bank 访问规则性，稀疏互连可以静态保证无对齐引起的 bank 冲突
- 硬件预取效率最高

**代价**：
- 对小工作负载(M=1, 小K)，A 填充最多 120B，每个 B 填充最多 56B

### 配置 4：(a=4, b=2, c_d=4) — 减小 D 对齐

| 属性 | 值 |
|------|-----|
| A 对齐 | 32 B (4 banks) |
| B 对齐 | 16 B (2 banks) |
| D 对齐 | 32 B (4 banks) |
| D 断言 | 64 % 32 = 0 PASS |

**动机**：
- D 写入器每拍输出 64B (8通道×8字节)，32B 对齐意味着每次写入起点在 4-bank 边界
- 连续两拍 D 写入可跨越两个 32B 页，但仍在一个 64B 对齐块内

**优势**：
- 更紧凑的 D 缓冲区布局
- 对输出尺寸为 32B 而非 64B 整数倍的工作负载，每个输出缓冲区节省最多 32B

**风险**：
- 如果硬件 D 写入器的后处理流水线（rescale 单元）要求 64B 对齐，降低到 4 可能导致错误
- 需要实际仿真验证

## 5. 配置对比总结

| 配置 | a | b | c_d | A 对齐 | B 对齐 | D 对齐 | 特点 |
|------|---|---|-----|--------|--------|--------|------|
| **当前** | 4 | 2 | 8 | 32 B | 16 B | 64 B | 平衡方案，匹配 tcdm_logic_word_size |
| **Config 1** | 1 | 1 | 1 | 8 B | 8 B | 8 B | 最小内存占用，最大冲突风险 |
| **Config 2** | 8 | 4 | 8 | 64 B | 32 B | 64 B | 对称读取器对齐，减少 B 冲突 |
| **Config 3** | 16 | 8 | 8 | 128 B | 64 B | 64 B | 最大规则性，完美 tile 对齐 |
| **Config 4** | 4 | 2 | 4 | 32 B | 16 B | 32 B | 减小 D 对齐，测试 32B 充分性 |

## 6. 设计原理与推荐

当前配置 (a=4, b=2, c_d=8) 的设计反映了 `tcdm_logic_word_size` 的层级：

| 字宽模式 | 每字节数 | 对应粒度 |
|---------|---------|---------|
| 256-bit | 32 B | a = 4 (32/8) |
| 128-bit | 16 B | b = 2 (16/8) |
| 64-bit × 8ch | 64 B | c_d = 8 (64/8) |

**推荐**：
- 对于 Int16x4 工作负载，当前配置是最佳平衡点
- 如需最大化 TCDM 利用率（超大矩阵），可考虑 Config 1 (全部降为1)
- 如需最高 bank 访问规则性（性能优先），可考虑 Config 3 (全部提升到 tile 级对齐)
- Config 4 仅在 D 写入器确认支持 32B 对齐后才安全使用

## 7. 对当前工作负载的影响

### Scaled 1/16 (K=16, N=22)

所有缓冲区尺寸已是 64B 的整数倍，四种配置的内存布局完全相同。粒度差异仅影响硬件层面的 bank 访问对齐规则。

### Full-size (K=256, N=352)

同样，因为 tile 尺寸（A=128B, B=64B, D=64B）都是最大粒度的整数倍，所有配置产生相同的内存布局。

**结论**：对于 Int16x4 Shape S0 (meshRow=8, tileSize=8, meshCol=4) 的任何工作负载，粒度参数的选择不影响内存占用，仅影响 bank 访问的硬件层面规则性。当前 (4,2,8) 配置已经是理论最优。
