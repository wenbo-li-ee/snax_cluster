## Errors Encountered

### E1: Stale library .o file → accel=0

**Symptom**: After rebuilding ELFs, simulation shows `accel=0, streamer=0, wall=2863`.
VersaCore never starts.

**Root cause**: `sw/snax/dual-versacore-swiglu/build/snax-dual-versacore-swiglu-lib.o`
was compiled at 16:36 when streamer_csr_addr_map.h was regenerated at 19:09.
The DUAL_VC_START CSR address (1053) was baked in from the old header (wrong value).
The ELF linked against the stale `.o` — CSR writes went to wrong addresses.

**Fix**: `make -C sw/snax/dual-versacore-swiglu clean && make` before rebuilding apps.

### E2: Simulation binary GLIBCXX version mismatch

**Symptom**: `./bin/snitch_cluster.vlt: /lib64/libstdc++.so.6: version GLIBCXX_3.4.31 not found`

**Fix**: Run with `LD_LIBRARY_PATH="$HOME/...snax_cluster/.pixi/envs/default/lib:$LD_LIBRARY_PATH"`

### E3: make CFG_OVERRIDE needed for datagen

**Symptom**: `IsADirectoryError` when running `make` from app directory without CFG_OVERRIDE.

**Fix**: Always pass `CFG_OVERRIDE=cfg/snax_dual_versacore_int16x4_cluster.hjson`.

## Notes

- The previous attempt used a FIFO-based silu_multilane (without CE). This task replaces it with the spec-mandated CE-based approach.
- The Scala generator `$$clog2(...)` syntax (double `$`) is intentional: in Scala string interpolation with `s"""..."""`, a single `$` would be interpreted as interpolation, so `$$` is needed to emit a literal `$`.
- The shared library (`snax-dual-versacore-swiglu-lib.o`) must ALWAYS be rebuilt after RTL generation regenerates `streamer_csr_addr_map.h`. The Makefile does not track this dependency automatically.
