# FP16 输入、INT4 权重 Dual VersaCore SwiGLU 开发日志

日期：2026-07-29

## 目标

- 保留现有 INT16×INT4 Dual VersaCore SwiGLU。
- 新增 FP16×INT4 配置。
- VersaCore 的 FP32 输出直接进入 FP32 SiLU / FP32 elementwise multiply。
- 去掉两路输入 rescale 和 elementwise multiply 后的 rescale。
- 两个写回路径都在写回前把 FP32 转为 FP16。
- 新增同时覆盖 mode 0（SwiGLU）与 mode 1（双路 GEMM）的易读测试 app。
- 在 `barnard3` 容器内完成 RTL 生成、软硬件构建与 VLT 仿真。

## 初始盘点

- 基准配置：
  `target/snitch_cluster/cfg/snax_dual_versacore_int16x4_multidim_spatial_k8_8x4_4lane.hjson`
- 现有生成器：
  `hw/chisel_acc/src/main/scala/snax_acc/versacore/DualVersaCoreSwigluGen.scala`
- 现有 SiLU 使用 6 段二次多项式，断点与系数保存在
  `silu_out16_balanced_pkg.sv`，当前实现为定点 Q 格式。
- 仓库已有浮点基础单元：
  - `fp_mul.sv`：支持 FP32×FP32，并可通过 `FpFormat_out` 选择 FP32/FP16 输出。
  - `fp_add.sv`：支持不同输入/输出浮点格式。
  - VersaCore 的 FP16×INT4 乘法使用现有 `fp_mul_int.sv`。
- 当前工作树已有与本任务无关的修改；本任务不覆盖或清理这些修改。

## 设计决定

1. 保持 streamer 拓扑、端口宽度、CSR 数量和数组形状与基准配置一致；使用新的
   `snax_acc_name=snax_dual_versacore_swiglu_fp16x4` 和 Bender target，
   以便新旧两种加速器生成物并存。
2. 通过 VersaCore 数据类型配置识别 FP16×INT4，使同一个生成器分别生成旧整数 postprocess 或新浮点 postprocess；旧整数配置和 app 保持可用。
3. FP32 SiLU 沿用原来的 7 个断点及 6 组二次多项式系数，将定点值按原 Q 格式换算为 IEEE-754 FP32 常量。
4. mode 0 数据流：
   `VC0 FP32 -> FP32 SiLU -> FP32 elementwise multiply <- VC1 FP32 -> FP32-to-FP16 -> Writer0`。
5. mode 1 数据流：
   `VC0 FP32 -> FP32-to-FP16 -> Writer0`，
   `VC1 FP32 -> FP32-to-FP16 -> Writer1`。
6. 保留 23 个 RW CSR，以保持框架和软件库 ABI 一致；旧 rescale CSR 在浮点 postprocess 中保留为兼容占位但不参与计算。

## 调试记录

### RTL 生成

在 `barnard3` 容器中执行：

```sh
make -C target/snitch_cluster rtl-gen \
  CFG_OVERRIDE=cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson
```

结果：成功。生成了独立目录
`target/snitch_cluster/generated/snax_dual_versacore_swiglu_fp16x4/`。
检查确认 shell 中没有未替换的模板占位符，生成的 `VersaCore.sv`
包含 FP16×INT4 乘加路径和 FP32 输出路径。

将新配置的 template 名、加速器 target 以及 A/C/D 浮点类型归一化回基准值后，
用 HJSON 结构化比较得到 `normalized_cfg_equal=True`；因此 streamer、端口、
CSR、阵列形状、granularity、TCDM 和 cluster 其余参数与基准配置一致。

### 软件构建

在同一容器、同一 `CFG_OVERRIDE` 下执行：

```sh
make -C target/snitch_cluster sw \
  CFG_OVERRIDE=cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson
```

结果：成功生成
`snax-dual-versacore-fp16x4-swiglu-test.elf`。

### Verilator 构建问题与修复

第一次 VLT 构建时，`target/snitch_cluster/generated/bender_targets.tmp`
仍缓存旧的 INT16×INT4 target，新 FP shell 没有被加入编译清单。
按工作流重新生成 target 清单：

```sh
util/snaxgen/snaxgen.py \
  --cfg_path=target/snitch_cluster/cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson \
  --get_bender_targets \
  > target/snitch_cluster/generated/bender_targets.tmp
```

然后使用容器内实际安装路径设置 Verilator：

```sh
export PATH=/pixi/.pixi/envs/default/bin:/tools/riscv/bin:$PATH
export VERILATOR_ROOT=/pixi/.pixi/envs/default/share/verilator
make -C target/snitch_cluster bin/snitch_cluster.vlt -j$(nproc) \
  CFG_OVERRIDE=cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson
```

结果：成功。Verilator 5.034 完成 785 个模块的展开和模型链接。

### 闭环仿真

直接运行新 ELF：

```sh
./target/snitch_cluster/bin/snitch_cluster.vlt \
  ./target/snitch_cluster/sw/apps/snax-dual-versacore-fp16x4-swiglu-test/build/snax-dual-versacore-fp16x4-swiglu-test.elf
```

输出：

```text
Mode 0 cycles: accelerator=4, streamer=42
Mode 0 SwiGLU: PASS, errors=0
Mode 1 cycles: accelerator=8, streamer=25
Mode 1 Writer 0: PASS, errors=0
Mode 1 Writer 1: PASS, errors=0
FP16xINT4 dual VersaCore total errors: 0
```

mode 0 Writer 0 写回地址为 `DELTA_LOCAL_MODE0_D0=3072`，写回内容已经由
硬件转换为 FP16。mode 1 Reader A 直接读取相同地址，不经过软件转换或搬移，
从而验证了 FP32→FP16 写回后的闭环；mode 1 两路结果分别写到
`DELTA_LOCAL_MODE1_D0=7168` 和 `DELTA_LOCAL_MODE1_D1=7240`。
mode 0 的第一行输入覆盖 6 个 SiLU 多项式分段，因而仿真不仅覆盖中间区间，
也覆盖最左和最右两组 FP32 系数。

## 最终结果

- 旧 INT16×INT4 配置、整数 postprocess 和测试 app 均未删除。
- 新 FP16×INT4 路径使用仓库已有 `fp_add`、`fp_mul` 和 VersaCore
  FP16×INT4 基础模块。
- 两个 writer 前均有基于现有 `fp_mul` 格式转换能力实现的
  FP32→FP16 narrowing。
- 完整 `rtl-gen -> sw -> VLT -> 仿真` 流程通过，三项检查总错误数为 0。

## B Reader granularity 调整

根据
`snax_dual_versacore_int16x4_multidim_spatial_k8_8x4_4lane_bgran2_highgran_search.hjson`
调整新 FP16×INT4 cfg：

- A Reader sparse access granularity 保持 `1`。
- B0、B1 Reader sparse access granularity 从 `1` 改为 `2`。
- 两个单通道 Writer 的 access granularity 保持 `1`。
- `granularity_a=4`、`granularity_b=2`、`granularity_c_d=2` 原本已经和
  参考 cfg 相同，无需修改。
- sparse fan-in 从 `34` 降为
  `16/1 + 8/2 + 8/2 + 1/1 + 1/1 = 26`。

参考 cfg 中另外存在 DMA FIFO、wide-xbar timing 和 XDMA
gather/scatter 等差异，这些不属于 streamer granularity，因此没有复制。

重新执行：

```sh
make -C target/snitch_cluster rtl-gen \
  CFG_OVERRIDE=cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson
make -C target/snitch_cluster sw \
  CFG_OVERRIDE=cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson
make -C target/snitch_cluster bin/snitch_cluster.vlt -j$(nproc) \
  CFG_OVERRIDE=cfg/snax_dual_versacore_fp16x4_multidim_spatial_k8_8x4_4lane.hjson
```

RTL 生成日志确认 accelerator 部分的 sparse 配置为：

```text
[[16,1], [8,2], [8,2], [1,1], [1,1]]
```

随后直接运行双 mode ELF，结果：

```text
Mode 0 cycles: accelerator=4, streamer=42
Mode 0 SwiGLU: PASS, errors=0
Mode 1 cycles: accelerator=8, streamer=25
Mode 1 Writer 0: PASS, errors=0
Mode 1 Writer 1: PASS, errors=0
FP16xINT4 dual VersaCore total errors: 0
```

B0/B1 granularity 提升到 2 后，当前数据地址与 channel/bank parity
保持兼容；完整重新生成的高 granularity VLT 闭环仿真通过。
